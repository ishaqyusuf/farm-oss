# Coding Standards

## Purpose
This file defines coding standards for contributors in this repository.

## How To Use
- Update when the team agrees on patterns that should be repeated.
- Keep standards practical and enforceable.
- Link to framework-specific guides when they are added.

## Standards
- Prefer TypeScript for application code.
- Keep modules small and explicit.
- Use clear domain names aligned with farm operations language.
- Avoid duplication of business rules across apps and services.
- Add focused tests around domain calculations and analytics logic.
- Prefer readable code over abstraction-heavy code.

## Documentation Rule
- If a change affects architecture, API, database, or workflow, update the brain in the same workstream.
